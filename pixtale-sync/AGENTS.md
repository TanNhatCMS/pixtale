# 项目约定
这一个同步工具

## 注释

- 每个函数/方法写一句简短注释，说明用途。
- 源文件在 import 之后空一行，再写模块说明。
- 复杂逻辑块加行内注释。
- Service 文件按“类型/常量、对外主要方法、内部辅助方法”的顺序组织；前端或其他模块直接调用的方法放在前面，辅助方法放在后面，避免辅助方法出现在类型和常量之前。

## 通用编码

- 变量、组件、回调名称要简洁且能看出含义。
- 避免过长命名、过度抽象，以及没有实际作用的防御性检查。

## 前端

- 不要为了抽象而拆组件：只有真正复用、或拆完能明显变清楚时，才放到 `src/components/`。
- 组件里的关键 props、state 要注明用途。
- 布局用 Ant Design，不要再加 Tailwind。

## 分层

```text
src/pages/       页面，直接调 service
src/components/  弹窗等复用块
src/service/     业务（list / add），SQL 写在这里
src/App.tsx      侧栏与切页
src-tauri/       窗口、插件、建表迁移
```

切页靠 `App` 的 `page` 状态，没有文件即路由。

当前页：同步任务、同步日志、设置。

## 加新页面

1. 在 `src/pages/` 新增页面文件。
2. 在 `src/App.tsx` 的菜单、标题和 `renderPage` 里挂上。
3. 该页若要读写数据，直接调 `src/service/`。

## 数据库
- 建表迁移在 `src-tauri/migrations/`，由 Rust 在启动时注册并执行。
